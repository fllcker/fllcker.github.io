# fllcker.github.io

Сайт-резюме. Vite + React + TypeScript, статическая сборка под GitHub Pages.

```bash
npm run dev        # разработка
npm run build      # прод-сборка в dist/ (+ 404.html и .nojekyll для Pages)
npm run preview    # посмотреть собранное
npm run typecheck  # только типы
```

## Где что лежит

| Что | Где |
| --- | --- |
| **Весь текст и все данные** | [src/content.ts](src/content.ts) |
| Дизайн-система целиком | [src/styles.css](src/styles.css) |

## Как дополнять

Вёрстку трогать не нужно — всё рендерится из данных в `src/content.ts`.

- **Новый проект** → объект в `projects`. Он сам появится в индексе, в секции
  «Работы» и получит страницу `/work/<slug>`. На главной целиком показываются
  последние `featuredCount` работ, остальные уходят в компактные строки
  индекса — глубина у них уже есть на собственных страницах.
- **Новый блок внутри проекта** → объект в `blocks`. Четыре вида: `prose`
  (абзацы), `points` (тезис + пояснение), `figures` (крупные цифры),
  `schematic` (схема архитектуры). У `prose` есть флаг `unfinished: true` —
  блок тогда сам сообщает читателю, что дописывается.
- **Новая технология** → строка в `stack` с полем `tier`: `core`, `working`
  или `applied`. Определения ступеней и их вес на карте — в `tiers`.
- **Новый язык** → строка в `languages`: `reach` (0..1) задаёт длину черты,
  `gloss` необязателен — родному языку нечего пояснять.
- **Новый контакт** → строка в `contacts`. Ровно один помечается
  `primary: true` — он набирается во всю ширину листа, остальные уходят в
  строку под ним.

Каждое текстовое поле — объект `{ ru, en }`. Оба языка обязательны: это не
перевод, а контент, и вёрстка рассчитана на то, что русская строка длиннее.

### Схемы архитектуры

Узлы задаются координатами в клетках сетки, а не в пикселях. Рамка сама растёт
под длину подписи, кадр сам считается по фактическим габаритам — длинное имя
узла не обрежется. `emphasis: true` — единственный узел, который несёт смысл
всей схемы (рисуется белым). `async: true` на связи — пунктир, для фоновых и
асинхронных путей.

Схема держит `min-width: 460px`: ниже подписи ушли бы в нечитаемый кегль,
поэтому на узком экране она прокручивается внутри своего контейнера, а под ней
появляется подсказка об этом.

### Карта стека

Площадь клетки — это ступень, а не популярность технологии: вес берётся из
`tiers[].weight`, раскладку считает squarified treemap. Ниже 430px карта
уступает место вертикальному списку — в клетке прикладного там остаётся около
36 пикселей свободной ширины, куда слово «Прикладное» не встаёт даже
обрезанным. Обе разметки лежат в документе, переключает их пара правил в CSS.

### Подпись в контактах

Кегль главного адреса не выводится из `vw`, а измеряется: строка ставится в
пробный кегль, снимается её реальная ширина, дальше пропорция. Поэтому адрес
любой длины садится ровно по ширине листа, и смена почты остаётся правкой
данных, а не вёрстки.

## Адаптивность

Брейкпоинты взяты из замеров, а не из списка типовых, и все правки живут в
`max-width`- и `pointer`-запросах — десктопная раскладка ими не затрагивается.

| Граница | Что происходит |
| --- | --- |
| 880px | примечание в клетке карты стека скрывается (ниже оно обрезается) |
| 500px | под схемой появляется подсказка о горизонтальной прокрутке |
| 430px | карта стека уступает место списку |
| `pointer: coarse` | площади нажатия растут до 44px, нарисованное не двигается |

Правила по указателю, а не по ширине: ноутбук с сенсорным экраном сообщает
`fine` и мобильных правил не получает, планшет в 1024px — получает.

## Деплой

Пушем в `master` — дальше [GitHub Actions](.github/workflows/deploy.yml)
собирает и публикует. В настройках репозитория Pages должен стоять
**Source: GitHub Actions**, иначе Pages будет раздавать корень ветки, где
лежит исходный `index.html` со ссылкой на `/src/main.tsx`.

Pages кормится артефактом сборки, а не веткой: класть `dist/` в репозиторий
пришлось бы коммитом на каждую правку текста.

Репозиторий назван `fllcker.github.io`, то есть это **user page** и отдаётся с
корня домена — поэтому `base: '/'` в [vite.config.ts](vite.config.ts). Если
сайт переедет в обычный репозиторий, `base` станет `'/<имя-репозитория>/'`.

`npm run build` кладёт в `dist/` две вещи сверх обычной сборки:

- `404.html` — копия `index.html`. Pages отдаёт статику, поэтому прямая ссылка
  вида `/work/anitype` без него вернула бы 404; с ним Pages отдаёт оболочку
  приложения, а роутер разбирает путь на клиенте.
- `.nojekyll` — чтобы Pages не прогонял сборку через Jekyll.

## Шрифты

Geist и Geist Mono лежат локально в `public/fonts/`, подключаются через
`public/fonts/geist.css`. Пакет `@fontsource/geist-sans` использовать нельзя:
он собран **только с latin**, кириллицы в нём нет. Файлы здесь нарезаны на
сабсеты `latin`, `latin-ext`, `cyrillic`, `cyrillic-ext` — браузер тянет
только нужное (около 43 kB для русского читателя на одном начертании).

## Дизайн

Одно правило держит всю страницу: волосяная линейка в 1px. Нет карточек, нет
скруглений, нет теней, нет второго цвета — иерархию несут кегль и яркость.
Наведение гасит соседей, а не подсвечивает выбранное.

Контракт направления живёт HTML-комментарием в [index.html](index.html) — он
объясняет, почему страница устроена именно так; не удаляйте его. Полные
правила системы — в `docs/private/DESIGN.md` (рабочие материалы, не в гите).
