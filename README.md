# fllcker.github.io

Сайт-резюме. Vite + React + TypeScript, статическая сборка под GitHub Pages.

```bash
npm run dev        # разработка
npm run build      # прод-сборка в dist/ (+ 404.html и .nojekyll для Pages)
npm run preview    # посмотреть собранное
npm run typecheck  # только типы
```

## Где что лежит

| Что | Где |
|---|---|
| **Весь текст и все данные** | [src/content.ts](src/content.ts) |
| Дизайн-система целиком | [src/styles.css](src/styles.css) |
| Главная (индекс) | [src/routes/Index.tsx](src/routes/Index.tsx) |

| Шрифты Geist (локально, с кириллицей) | [public/fonts/](public/fonts/) |

## Как дополнять

Вёрстку трогать не нужно — всё рендерится из данных в `src/content.ts`.

- **Новый проект** → добавить объект в `projects`. Он сам появится в индексе, в
  секции «Работы» и получит страницу `/work/<slug>`.
- **Новый блок внутри проекта** → добавить объект в `blocks` этого проекта.
  Доступны четыре вида: `prose` (абзацы), `points` (тезис + пояснение),
  `figures` (крупные цифры), `schematic` (схема архитектуры).
- **Новая технология** → строка в `stack`. Поле `magnitude` (1–5) рисуется
  кеглем: глубину видно, не читая цифр.
- **Новый контакт** → строка в `contacts`.

Каждое текстовое поле — объект `{ ru, en }`. Оба языка обязательны: это не
перевод, а контент, и вёрстка рассчитана на то, что русская строка длиннее.

### Схемы архитектуры

Узлы задаются координатами в клетках сетки, а не в пикселях. Рамка сама
растёт под длину подписи, кадр сам считается по фактическим габаритам —
длинное имя узла не обрежется. `emphasis: true` — единственный узел, который
несёт смысл всей схемы (рисуется белым). `async: true` на связи — пунктир,
для фоновых и асинхронных путей.

## ⚠ Что обязательно заменить перед публикацией

**Весь контент сейчас — заглушка.** Ни одно утверждение на сайте не проверено.
Ищите в `src/content.ts` пометку `PLACEHOLDER`:

- **Проекты `Orbit` и `Ledger`** — названия, периоды, роли, описания, решения
  и схемы архитектуры выдуманы целиком. Это каркас под ваши две реальные
  работы, а не описание чего-то существующего.
- **Все цифры в блоках «Чем закончилось»** — `4.2M событий в сутки`,
  `0 потерянных событий за 14 месяцев`, `~40 мин на пересчёт` и остальные.
  Это самое опасное место: цифры выглядят как проверяемые факты. Заменить
  на настоящие или удалить блок `figures` целиком.
- **Контакты** — `hey@fllcker.dev`, `@fllcker`, ссылки на GitHub. Ни один
  адрес не настоящий.
- **Ссылки в `links` у проектов** — ведут на заглушку.
- **`identity.since`** (`2019`), `availability`, `location` — не подтверждены.
- **Уровни `magnitude` в `stack`** — расставлены на глаз, поправьте под себя.

Пока заглушки на месте, в индексе, в подвале и на страницах проектов стоит
пометка «Черновик: содержание временное». Когда замените контент — уберите
`ui.placeholderNotice` из `src/content.ts` и три места, где он выводится.

## Деплой на GitHub Pages

Репозиторий назван `fllcker.github.io`, то есть это **user page** и отдаётся
с корня домена — поэтому `base: '/'` в [vite.config.ts](vite.config.ts).
Если сайт когда-нибудь переедет в обычный репозиторий, `base` станет
`'/<имя-репозитория>/'`.

`npm run build` кладёт в `dist/`:

- `404.html` — копия `index.html`. Pages отдаёт статику, поэтому прямая ссылка
  вида `/work/orbit` без него вернула бы 404; с ним Pages отдаёт оболочку
  приложения, а роутер разбирает путь на клиенте.
- `.nojekyll` — чтобы Pages не прогонял сборку через Jekyll.

Публиковать содержимое `dist/` (ветка `gh-pages` или GitHub Actions).

## Шрифты

Geist и Geist Mono лежат локально в `public/fonts/`, подключаются через
`public/fonts/geist.css`. Пакет `@fontsource/geist-sans` использовать нельзя:
он собран **только с latin**, кириллицы в нём нет. Файлы здесь нарезаны на
сабсеты `latin`, `latin-ext`, `cyrillic`, `cyrillic-ext` — браузер тянет
только нужное (около 43 kB для русского читателя на одном начертании).

## Дизайн

Направление и правила системы записаны в `docs/private/DESIGN.md` (не в гите —
рабочие материалы). Контракт направления
живёт HTML-комментарием в `index.html` — не удаляйте его, он объясняет, почему
страница устроена именно так.
